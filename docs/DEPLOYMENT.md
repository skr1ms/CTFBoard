# Deployment

AstroCTFb is deployed through `setup.sh` and Docker Compose. The script keeps generated files current, initializes/unseals Vault, seeds secrets, and starts the stack.

## First Deploy

Prerequisites:

- Linux server with Docker Engine and Docker Compose plugin.
- DNS A records for the platform root and subdomains: `DOMAIN`, `API_DOMAIN`, `GRAFANA_DOMAIN`, `VAULT_DOMAIN`, `S3_DOMAIN`.
- Optional external services: Resend, GitHub OAuth, Google OAuth, Telegram bot.

Recommended path:

```bash
git clone https://github.com/TakuyaYagam1/AstroCTFb.git
cd AstroCTFb
cp .env.example .env
chmod 600 .env
$EDITOR .env
./setup.sh start
```

Fill the `REQUIRED` block in `.env` before `start`. Leave optional secrets empty if you want `setup.sh` and Vault init to generate them.

Interactive path:

```bash
./setup.sh
```

When `.env` is missing, this opens the first-run wizard and writes a structured `.env`.

## Environment Model

`.env.example` is the source of truth for supported variables, their order, defaults, and comments.

High-level groups:

- `REQUIRED`: domains, public URLs, bootstrap passwords, SeaweedFS S3 keys, admin email.
- `OPTIONAL`: Vault-seeded app secrets and setup token. Empty values are generated on first start where supported.
- `INTEGRATIONS`: Resend, OAuth providers, Telegram alerts.
- `DEFAULTS`: app identity, runtime defaults, storage settings, HAProxy, SeaweedFS ports, image tags.

Important behavior:

- Infrastructure bootstrap credentials stay in `.env` because containers need them at startup.
- Runtime app secrets are seeded into Vault under `secret/ctf-platform/*`.
- Backend reads database, Redis, S3, JWT, admin, OAuth, and Resend secrets from Vault using `VAULT_BACKEND_TOKEN`, a setup-generated read-only Vault token.
- Vault `ROOT_TOKEN` stays in `.vault-keys` for setup and operations; do not put it in `.env`.
- `SEAWEED_S3_ACCESS_KEY` and `SEAWEED_S3_SECRET_KEY` are used by SeaweedFS S3, Vault storage seed, backend storage access, and the official SeaweedFS Admin UI login.
- `SETUP_TOKEN` is required by the browser setup wizard and is generated by `setup.sh start` when empty.

## Generated Files

`setup.sh start` keeps these derived files current:

- `deployment/seaweedfs/s3.json` from `.env` S3 credentials.
- `monitoring/alertmanager/alertmanager.yml` from Telegram settings.
- `.vault-keys` after Vault initialization. Back it up immediately.

Never commit `.env`, `.vault-keys`, production `s3.json`, or generated secrets.

## Runtime Endpoints

Public endpoints:

- `https://${DOMAIN}`: board frontend.
- `https://${API_DOMAIN}/api/v1`: backend REST API, WebSocket, SSE.
- `https://${S3_DOMAIN}`: browser traffic goes to SeaweedFS Admin UI; SigV4 and presigned S3 requests go to the S3 gateway.

Operator endpoints:

- Grafana: `https://${GRAFANA_DOMAIN}` if your IP is allowlisted, or SSH tunnel to `localhost:3000`.
- Vault UI: SSH tunnel to `localhost:8200`; production compose binds Vault to `127.0.0.1`.
- HAProxy stats: SSH tunnel to `localhost:8405/stats`.

Tunnel example:

```bash
ssh -L 8200:127.0.0.1:8200 -L 3000:127.0.0.1:3000 root@your-server-ip
```

## Operations

Common commands:

```bash
./setup.sh start
./setup.sh stop
./setup.sh restart
./setup.sh status
./setup.sh logs
./setup.sh reconfigure
```

Secrets:

```bash
./setup.sh secrets edit
./setup.sh secrets rotate
./setup.sh secrets rotate-flag
./setup.sh secrets rotate-s3
```

Reset paths:

```bash
./setup.sh reset config
./setup.sh reset data
./setup.sh reset all [--all-images]
./setup.sh uninstall [--all-images]
```

Use `reset config` for a safe early redo that keeps Docker volumes. Use `reset data` only when deleting database, Vault, uploads, Grafana data, and certificates is acceptable.

## Verification

After deploy:

```bash
docker compose --env-file .env -f deployment/docker/docker-compose.yml ps
docker exec vault vault status
curl -fsS "https://${API_DOMAIN}/api/v1/health"
curl -fsS "https://${API_DOMAIN}/api/v1/openapi.json" >/dev/null
```

Expected:

- Core containers are `healthy`.
- Vault is initialized and unsealed.
- Backend healthcheck succeeds.
- Frontend login page loads.
- SeaweedFS Admin UI opens at `S3_DOMAIN` for allowlisted operator traffic.
- Challenge file downloads stream through authenticated signed backend URLs.

## Troubleshooting

- Vault will not unseal: check `.vault-keys`, the Vault root token used by setup operations, and `docker logs vault`.
- Backend restart loop: check Vault status, DB readiness, and `docker logs backend`.
- SeaweedFS S3 returns 403: compare `.env` `SEAWEED_S3_*`, SeaweedFS container env, and Vault `secret/ctf-platform/storage`.
- TLS certificate missing: first run uses a self-signed bootstrap cert until certbot completes. Start with `USE_LE_STAGING=true` to avoid Let's Encrypt rate limits.
- Grafana unhealthy: verify `GRAFANA_ADMIN_PASSWORD` and persistent Grafana volume ownership.
- Login loop: verify `FRONTEND_URL`, `CORS_ORIGINS`, `SECURE_COOKIES`, and whether the site is actually served over HTTPS.
